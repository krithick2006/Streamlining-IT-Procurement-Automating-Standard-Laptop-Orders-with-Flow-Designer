Streamlining IT Procurement: Automating Standard Laptop Orders with Flow Designer

Six phases, each with the document that closes it. Built from the project slides and the original activity write-up (ServiceNow, Flow Designer, Service Catalog).

Phase 1: Initiation

Deliverable: Project Charter

ProjectAutomating standard laptop orders with a Flow Designer flow
InstitutionMisrimal Navajee Munoth Jain Engineering College
TeamSanjay, Krithick, Selva Bharath, Tharun, Rohith
PlatformServiceNow: Flow Designer, Service Catalog, Maintain Items, Approvals

Problem statement

IT procurement lacks automation, causing delays and manual overhead. Standard laptops need configuration, a step that is easily missed or delayed, so users wait for devices that are not ready on arrival and IT effort is spent inefficiently.

User story

As a member of the IT procurement team, I want a streamlined process for ordering standard laptops so that tasks are generated automatically and assigned to the hardware team, so laptops are configured promptly on arrival, user wait times drop and manual intervention is minimal.

Objectives and success measures

ObjectiveMeasure
Seamless, timely configuration for requestersConfiguration task exists as soon as the order is processed
Less manual work and fewer errorsZero manually created tasks for this item
Better task allocationEvery task lands in the Hardware group with no reassignment

Scope

  • In: Standard Laptop item (Lenovo Carbon x1), approval, one flow, auto-created catalog task for Hardware.
  • Out: Other catalog items, asset records, notifications, SLAs, vendor ordering.

Phase 2: Requirements and design

Deliverables: Requirements Specification, Solution Design

Functional requirements

IDRequirement
FR1Users can order Standard Laptop from Service Catalog > Hardware.
FR2An approver can approve the request from the Approvers tab.
FR3A flow named "Standard laptop task" runs on the Service Catalog trigger.
FR4The flow creates a Catalog Task (sc_task) linked to the Requested Item.
FR5The task has short description and description "Laptop needs to Configured", Assignment group Hardware, Approval Approved.
FR6The flow is attached to the item's Process Engine tab, replacing other automations.

Non-functional: runs as System User, Global application, no manual step after approval.

Process flow

flowchart LR
A[User orders Standard Laptop] --> B[Request and RITM created]
B --> C[Approver approves]
C --> D[Flow: Standard laptop task]
D --> E[Create Catalog Task]
E --> F[Assigned to Hardware group]

Design components

ComponentDesign
FlowName Standard laptop task, Global, Run As System User
TriggerService Catalog
ActionCreate Catalog Task, Requested Item from trigger, table sc_task
Catalog itemStandard Laptop, Hardware category, flow set in Process Engine tab
Open point to confirm in design review: the Service Catalog trigger fires when the item is ordered, and the task is created with Approval preset to Approved. The slides describe the task appearing after approval, so verify the observed timing and, if the task must wait for the approver, add a Wait for Condition or approval action before Create Catalog Task.

Phase 3: Build

Deliverable: Build and Configuration Runbook

Milestone 1: Create the flow

  1. All > Flow Designer (Process Automation) > New > Flow.
  2. Name "Standard laptop task", Application Global, Run As System User, Submit.
  3. Add a trigger: Service Catalog, Done.
  4. Add an action: Create Catalog Task. Drag the trigger's Requested Item into Requested Item; table fills as Catalog Task.
  5. Short description "Laptop needs to Configured". Add field values: Description same text, Assignment group Hardware, Approval Approved. Leave the rest default, Done.
  6. Save, then Activate and confirm.

Milestone 2: Assign the flow to the item

  1. All > Maintain Items, open Standard Laptop.
  2. Process Engine tab: remove other automations, add Flow, select "Standard laptop task".
  3. Save the record.
Source text says "Laptop need to Configured" while the demo screenshots show "Laptop needs to Configured". Pick one wording and use it everywhere.

Phase 5: Deployment and handover

Deliverables: Go-live Checklist, User Guide, Rollback Plan

Go-live checklist

  • Flow Active, Application Global, Run As System User
  • Process Engine tab holds only the flow
  • Hardware group exists and has members
  • All test cases passed, UAT signed
  • Hardware team briefed on the new task

User guide: ordering and approval

  1. All > Service Catalog > Hardware > Standard Laptop.
  2. Click Order Now, then open the Request Number on the Order Status page.
  3. Approver: Approvers tab, right-click the approval, Approve.
  4. Open the Requested Item, then Catalog Tasks, to see the Hardware task (for example SCTASK0010001).

Rollback plan

Deactivate the flow, then reselect the previous process engine on the Standard Laptop item. Create any pending tasks manually.

Phase 6: Closure

Deliverable: Project Closure Report

Results

  • Task creation is automatic, with no manual step.
  • Hardware receives work immediately, so configuration starts sooner.
  • Resource allocation is more consistent across the IT team.

Conclusion

Automating standard laptop procurement with Flow Designer removes manual overhead, shortens user wait times and improves IT productivity through a seamless ordering experience.

Lessons and next steps

  • Standardise the task wording and confirm trigger timing against approval.
  • Add notifications to the Hardware group and requester.
  • Extend the pattern to other standard hardware and add SLA tracking.
  • Report on order-to-ready time to prove the benefit.
